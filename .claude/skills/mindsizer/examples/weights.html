Where a model's habits live

Training, pretraining and RL alike, writes behaviour into billions of numbers: the weights. Context and external stores never change those numbers. They steer them, only while their text is in front of the model.

weights/

"In the weights" means a tendency spread across billions of numbers, not a rule written down somewhere

A language model is one fixed recipe, the architecture, plus a very large list of numbers, the weights or parameters. Given some text, the recipe uses the weights to score every possible next token and turns those scores into probabilities. Sampling one token, appending it and repeating produces a reply.

So a "habit", such as answering politely, hedging, or writing Python a certain way, is just that some continuations are more probable than others. No line anywhere says "be polite". It's natural to imagine one. Look for it.

That is all there is to find. Politeness, the fact about Paris and bracket-closing are each spread over very many of these numbers, and each number takes part in very many behaviours. Interpretability research tries to locate such features, and it is a hard, open problem.

weights/training/

Pretraining and RL edit the same numbers; what differs is the signal pushing them

Pretraining shows the model huge amounts of text and, at every position, nudges all the weights a little so the true next token becomes more likely. The result, the base model, mirrors its data: asked a question, it often just continues the page, the way a web document would.

Post-training starts from a copy of those weights and keeps nudging the same numbers. Supervised fine-tuning imitates example answers. Reinforcement learning samples the model's own replies, scores them with a reward (a model of human preferences, a test suite, a grader), and makes high-scoring replies more likely. It mostly reweights what the base model could already do. It also amplifies whatever the reward happens to favour, including what nobody intended.

Illustrative toy. Four reply styles stand in for billions of weights. Pretraining moves the odds toward how often each style appears in the text; RL raises each style in proportion to how much its reward beats the average. Real post-training also adds a penalty for drifting far from the base model.

Both stages write to one place. RL's habits end up "in the weights" exactly as pretraining's do.

step 0

Random numbers

Before training, the weights are random. The model produces gibberish.

pretraining

Nearly every weight moves

Over trillions of tokens, each step nudges the weights toward predicting the next token. Grammar, facts and styles of writing settle in as tendencies.

checkpoint saved

The base model

The weights are written to disk. This file never changes again. This is the sense in which the base model is fixed.

post-training

A copy is trained further

Fine-tuning and RL start from a copy of the base weights and change them again, usually by far less than pretraining did. The result is a new file: same architecture, different numbers.

release

Frozen for use

When the model is served, its weights are only read, never written. Every user talks to the same numbers.

conversation A

Behaviour shifts, weights don't

Your instructions and the chat so far sit in the context window. They change what the model does in this conversation. Zero weights change.

conversation ends

The context is gone

Nothing from conversation A remains in the model. If the agent wrote a note to a file or memory store before it ended, the note is the only thing that remains.

conversation B

The note comes back as text

The agent searches the store and pastes the note into its new context. The behaviour returns because the text is back in front of the model. The weights are still untouched.

a later training run

Only training writes weights

If a lab later trains on new data, which might include conversations, depending on its policy, the change lands in a new model. The released model's file stays as it was.

context/

The context window steers behaviour without changing a single weight, and it's gone when the conversation ends

Every next token is computed from the weights and all the text in the context: system prompt, conversation, pasted documents, tool results. Change the text and the same frozen weights produce different odds. Models can even pick up a new pattern from a few examples in the prompt. This is called in-context learning, and nothing is written back.

It's also bounded: the window holds a limited number of tokens, and strong trained habits can win against a weak instruction. Change what's in the context, then end the conversation.

store/

An external store lasts, but it only matters once it's read back into the context

Agents get memory across conversations by writing outside themselves: a notes file, a database, a search index. In a later session they look it up, and the retrieved text joins the context. Product "memory" features generally work this way rather than by retraining the model on each user.

That makes the store the opposite of the weights in the ways that matter. You can read it, edit it and delete it, but it does nothing unless it's retrieved. Pick where a habit lives, then put it through what happens to models.

The outcomes are the general pattern, simplified. Real systems mix all three.

summary/

So: training writes, context steers, stores remember

When someone says a habit is "in the weights", they mean training made it more probable, everywhere, for everyone using that model, until a new model replaces it. You can't open the weights and point at it, and you can't remove it by editing. You can only train again.

Anything in the context or a store is text the frozen model reads. It's specific to a conversation or a user, it's inspectable, and it vanishes or stays exactly as long as the text does.
